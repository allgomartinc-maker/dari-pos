# Qarz (customer credit) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a shop sell on qarz to named customers, take part payments, see each person's running balance and history, and send it all to the owner's Google Sheet.

**Architecture:** There is a ledger of signed entries per customer, and the balance is always the sum of those entries. Pure maths lives in a new `js/qarz.js`, unit-tested in Node. Storage is Dexie schema v2, with new `customers` and `ledger` tables. The screens live in `js/app.js` in a new "qarz" section, following the file's existing pattern. Qarz cash collected becomes a shift movement of type `qarz`, so the existing shift maths and the `Cash_Movements` sync carry it.

**Tech Stack:** Vanilla ES modules, Dexie (IndexedDB), node:test, Google Apps Script (tested with the vm fake in `tests/apps-script.test.mjs`), Playwright (Python) for the phone-size end-to-end run.

**Spec:** `docs/superpowers/specs/2026-11-14-qarz-design.md`

## Global Constraints

- Money is integer pul (1 AFN = 100 pul). Quantities keep grams (`round3`).
- UI copy is Dari, RTL, big touch targets. Every form field is ≥16px (existing CSS rule). Nothing may overflow at 375px wide.
- Rule: **cash covers this purchase first; anything extra pays down the customer's old qarz.**
- Ledger `type` ∈ `sale` (+credit), `payment` (−), `void` (−credit), `adjust` (±, manager, note required). Ledger rows are never deleted.
- A cashier may give qarz and receive payments. The **manager PIN** is needed to: go over a customer's `limit`, `adjust`, edit name/phone/limit, delete (only at balance 0, soft delete).
- Practice (🧪) carts can't go on qarz. No open shift means no qarz sale or payment.
- Receipts print the customer's name, never their phone.
- Every deploy bumps `VERSION` in `sw.js` (currently `dari-pos-v18`, so this is `v19`).
- Old Code.gs must not lose qarz rows: `customers` and `ledger` are marked synced only when the push response has `features` including `'qarz'`.

## Review Focus

1. **Same customer name typed twice** ("Ahmad" vs "ahmad "): the picker search must find the existing one (trimmed, case-insensitive, Dari digits in phone), and new-customer save warns if the name already exists. Test in Task 1 (`findCustomers`) and Task 3.
2. **Cash typed with Dari digits or separators** (۱٬۰۰۰): the split uses `parseMoney`, the same as the cash field. Test in Task 1 (`splitQarzPayment` takes pul; the UI test in Task 8 types ۱۰۰۰).
3. **Reprinting an old qarz receipt** must show the balance *at that time*, not today's. `balanceAfter` is stored on the sale. Test in Task 4.
4. **Voiding a sale that was already paid off** makes the balance negative and shows «دکان بدهکار است» (the shop owes them). Test in Task 1 (`balanceOf`) and Task 6.
5. **Phone offline for days, then the Sheet is upgraded:** queued qarz rows still arrive. Test in Task 7 (the feature gate).

### Task 1: Qarz maths (`js/qarz.js`)

**Files:**
- Create: `js/qarz.js`
- Test: `tests/qarz.test.mjs`

**Interfaces:**
- Produces:
  - `balanceOf(entries: Ledger[], customerId: string): number`. The sum of `amount` (pul).
  - `balancesById(entries): Map<customerId, {balance, lastAt}>`.
  - `splitQarzPayment({ total, cash, balance }): { cashReceived, credit, overpaid, newBalance, overBalance }`. All pul.
    - cash < total → `cashReceived = cash`, `credit = total - cash`, `overpaid = 0`.
    - cash ≥ total → `cashReceived = total`, `credit = 0`, `overpaid = cash - total`.
    - `newBalance = balance + credit - overpaid`.
    - `overBalance = overpaid > max(balance, 0)`.
  - `overLimit(customer, newBalance): boolean`. True when `customer.limit > 0 && newBalance > customer.limit`.
  - `findCustomers(customers, query): Customer[]`. Matches trimmed, case-insensitive name, or phone digits (Dari or Latin). Hides `deleted` unless their balance ≠ 0 (the caller passes balances). Sorted by balance, highest first.
  - `ledgerEntry({ customer, type, amount, receiptId?, shiftId?, by, note? }): Ledger`. Sets `id = randomId()`, `customerName`, `timestamp = updatedAt = now ISO`, `synced: 0`. Throws if `type === 'adjust'` and there is no note.
  - `qarzTotals(entries, range): { given, collected }`.
    - `given` = sum of `sale` minus `void` in range.
    - `collected` = −sum of `payment` in range.
  - `statementText({ storeName, customer, entries, balance }): string`. Dari text with: name, still owes, and the last 15 entries as `date · what · amount`.
- Consumes: `randomId`, `round3`, `formatMoney`, `dariDate`, `toDariDigits`, `toLatinDigits` from `js/logic.js`.
